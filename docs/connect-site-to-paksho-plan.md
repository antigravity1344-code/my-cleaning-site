# طرح: وصل کردن سایت نظافت به سرور پاکشو

**وضعیت:** طرح. هنوز کدی تغییر نکرده است.
**تاریخ:** ۹ نوامبر ۲۰۲۶
**تصمیم مالک:** «سایت را به سرور پاکشو وصل کن و سرور جدای سایت را کنار بگذار.»

## هدف
سایت فقط معرفی و فرم سفارش باشد. سفارش، قیمت، متخصص، کمیسیون و پنل مدیر از سرور پاکشو بیایند،
تا یک قاعدهٔ قیمت و یک پنل مدیر وجود داشته باشد.

## استقلال سایت (الزام مالک، ۹ نوامبر ۲۰۲۶)
یک مشتری ممکن است **فقط سایت نظافت** بخواهد و اپ موبایل نخرد. سایت باید بدون اپ کار کند و
برای هر مشتری جدا راه‌اندازی شود (برند، خدمت‌ها و تعرفهٔ خودش).

**تصمیم مالک (۹ نوامبر ۲۰۲۶):** هر مشتری سایت **سرور جدا** دارد؛ چندمستاجری در یک سرور نیست.

- هر مشتری یک نمونهٔ جدا از سرور (همان کد پاکشو) با پایگاه‌داده و تنظیمات جدا دارد.
- برند، دامنه و تعرفهٔ هر مشتری جدا است و داده‌ها با هم مخلوط نمی‌شوند.
- اپ پاکشو و سایت هر مشتری قاعدهٔ قیمت یکسان دارند، چون از یک کد می‌آیند.
- اگر سرور مشتری در دسترس نباشد، سایت پیام روشن نشان می‌دهد و سفارش ثبت نمی‌شود.
- هزینهٔ میزبانی و انتخاب سرور برای هر مشتری، تصمیم جداگانهٔ مالک است و هنوز انجام نشده.

## محدوده
**داخل:**
- حذف سرور جدای سایت (`server/`) و موتور قیمت آن (`pricingConfig.js`، `pricingEngine.js`) از مسیر سفارش.
- اتصال فرم سفارش سایت به API سفارش و نقل‌قول پاکشو (قیمت امضاشده از سرور پاکشو).
- پیگیری سفارش از همان API پاکشو.
- حذف پنل مدیر جدای سایت؛ مدیریت سفارش‌ها در پنل مدیر پاکشو.

**بیرون از محدوده (فعلاً):**
- درگاه پرداخت، پیامک و تخصیص واقعی متخصص. این‌ها هنوز وصل نیستند؛ `capabilities.ts` همچنان همه را `false` نگه می‌دارد.
- ادعاهای اعتباری (بیمه، نماد اعتماد، عضویت اتحادیه). همچنان غیرفعال می‌مانند تا مدرک معتبر باشد.
- محتوای بازاریابی و ظاهر سایت.

## پرسش‌هایی که قبل از کدنویسی باید مالک جواب دهد
1. **خدمت‌ها:** فهرست خدمت‌های سایت (نظافت منزل، محل کار، مبل‌شویی، راه‌پله، خانه‌تکانی) با خدمت‌های پاکشو یکی شوند؟ اگر نه، کدام خدمت‌ها فقط در سایت باشند؟
2. **کد تخفیف:** کدهای تخفیف سایت نگه داشته شوند یا حذف؟ (در پاکشو تخفیف کد جدا از تعرفه تعریف نشده است.)
3. **هویت مشتری:** مشتری سایت با شماره موبایل و OTP وارد شود (مثل اپ) یا بدون ورود سفارش بدهد؟
4. **داده‌های موجود:** سفارش‌های سرور جدای سایت واقعی‌اند یا فقط نمایشی؟ (طبق `DEMO_MODE` نمایشی‌اند؛ اگر چیزی واقعی نیست، بدون انتقال حذف می‌شوند.)

## مراحل پیشنهادی (هر مرحله در PR جدا)
1. **پیش‌نیاز در پاکشو:** API عمومی برای مشتری وب (نقل‌قول و ثبت سفارش با OTP). این کار در مخزن پاکشو است و باید طرحش جدا تأیید شود.
2. سایت: اتصال فرم سفارش به API پاکشو، با پرچم برای برگشت به حالت نمایشی.
3. سایت: حذف سرور جدای سایت و موتور قیمت آن، بعد از تأیید مرحلهٔ ۲.
4. سایت: حذف پنل مدیر جدای سایت، بعد از اینکه پنل پاکشو همه‌ی کارهای آن را پوشش دهد.

## توقف و تأیید
- هیچ merge بدون تأیید صریح مالک.
- اگر API پاکشو برای مشتری وب نیاز به تغییر قرارداد احراز هویت یا چندمستاجری داشت، متوقف شو و بپرس.
- اگر یکی از پرسش‌های بالا بی‌جواب بماند، کدنویسی آن بخش شروع نمی‌شود.

## پاسخ‌های مالک (۹ نوامبر ۲۰۲۶)
1. **خدمت‌ها:** همان خدمت‌های پاکشو. فهرست خدمت‌های سایت از پاکشو خوانده می‌شود.
2. **کد تخفیف:** بماند، به شرط اینکه با اپ تداخل نکند. تصمیم فنی: کد تخفیف فقط روی سفارش سایت ثبت می‌شود و موتور تعرفهٔ پاکشو تغییر نمی‌کند. قیمت نقل‌قول از سرور قفل می‌شود و تخفیف جدا از آن ثبت می‌شود.
3. **ورود مشتری:** سفارش بدون ورود ثبت شود؛ برای ثبت نهایی شماره موبایل و کد پیامکی (OTP) لازم است.
4. **سفارش‌های واقعی:** سفارش‌ها نمایشی‌اند و منتقل نمی‌شوند.
